# Adapter validation evidence

Accessed/tested 2026-10-09. Confidence high for measured executable behavior, no gameplay certification.

The real-runtime integration harness installs the original archives with the same hash/extraction service used by the application, then invokes only workspace-owned runtime processes.

- DuckStation -version returns its version text with exit 1. The upstream parser returns false for this informational mode; the test checks expected version output rather than treating exit 1 as a game launch success. [Source](https://github.com/stenzek/duckstation/blob/master/src/duckstation-qt/qthost.cpp).
- PCSX2 v2.8.2 likewise reports version via its CLI. Its -testconfig accepts SettingsVersion=1 and an isolated data path. [Qt host](https://github.com/PCSX2/pcsx2/blob/v2.8.2/pcsx2-qt/QtHost.cpp), [version check](https://github.com/PCSX2/pcsx2/blob/v2.8.2/pcsx2/VMManager.cpp).
- PPSSPP v1.20.4 Windows recognizes --config and --controlconfig in its Windows entrypoint. It uses installed.txt to choose memory-stick storage. It does not implement the newer development --help/--memstick behavior. The integration check starts its portable window, observes initialization, then closes only that owned process. [Pinned Windows source](https://github.com/hrydgard/ppsspp/blob/v1.20.4/Windows/main.cpp), [pinned NativeApp](https://github.com/hrydgard/ppsspp/blob/v1.20.4/UI/NativeApp.cpp).
- RPCS3 --help succeeds. Official PUP import and headless installation produce dev_flash files and a fresh “Successfully installed” log, then this build exits 0xC0000409 in headless teardown on this machine. The Hub precreates the log directory, removes stale success logs, and accepts that one code only with fresh success text and vsh.self/liblv2.sprx present. Other codes/incomplete installs fail. [Installer](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/rpcs3qt/main_window.cpp), [entrypoint](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/rpcs3.cpp), [VFS configuration location](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/vfs_config.cpp).
- Xenia Canary --help succeeds with the pinned archive. Storage/content roots and fullscreen arguments are separate tokens; title execution remains untested. [Entrypoint](https://github.com/xenia-canary/xenia-canary/blob/canary_experimental/src/xenia/app/emulator_window.cc).

The test found and corrected slow repeated solid-archive decompression, incorrect PPSSPP development-branch assumptions and the RPCS3 config/vfs.yml location. It did not prove controller correctness or rendering for a commercial game.

The downloaded DuckStation executable reports 0.1-12074-g697599c47 (dev). Its upstream release label is Latest Rolling Release; the archive SHA-256 is the immutable identity. The actual Xenia upstream download was additionally exercised through ProviderDownloader/RuntimeService, including redirect-host validation, SHA-256 verification, extraction and a subsequent offline reuse. The network test uses no emulator mirror or game media.
